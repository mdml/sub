# Architecture: crate layout

`sub` is one Cargo workspace. The SDK is the kernel; every other crate consumes it. Rationale: [`decisions/2026-08-27-workspace-layout.md`](decisions/2026-08-27-workspace-layout.md).

| Crate | Kind | Role |
|:--|:--|:--|
| `sub-sdk` | library | The kernel: the delegated-work model and the SDK. Owns the shared ACP client layer (`sub_sdk::acp`) and depends directly on the ACP SDK crate. |
| `sub-cli` | binary `sub` | Command-line surface for humans: bridge install, launch, wait, recover, cancel, list, and inspect. |
| `sub-mcp` | binary `sub-mcp` | MCP stdio server for agents: bridge install, launch, wait, recover, cancel, list, and inspect. |
| `sub-harness-fake` | library and binary `sub-harness-fake` | Programmable fake harness (ACP v1 over stdio) for the behavioral contract suite. Owns fixture loading, scenario scripting, and the replay server. Depends directly on `sub-sdk` and the ACP SDK crate. |
| `sub-adapter-claude` | library | Adapter for `claude`, through pinned `@agentclientprotocol/claude-agent-acp` 0.70.0. |
| `sub-adapter-codex` | library | Adapter for `codex`, through pinned `@agentclientprotocol/codex-acp` 1.6.2. |
| `sub-adapter-cursor` | library | Adapter for `cursor-agent`, which speaks ACP natively. |

Dependency direction: surfaces → adapters and `sub-sdk` → `agent-client-protocol`, `tokio`; `sub-harness-fake` → `sub-sdk`, `agent-client-protocol`, `tokio`. Only `sub-sdk` and the programmable fake depend directly on ACP types. Adapters construct SDK launch data and never depend on a surface.

The shared ACP client layer in `sub-sdk` spawns an agent process, negotiates protocol v1, creates, resumes, or replay-loads a session with adapter metadata, sets the requested harness-native permission mode and optional model, sends a prompt, consumes the update stream, captures unstable per-turn token usage, denies permission requests, cancels, and times out. The delegated-work kernel writes task/attempt state and a typed normalized event log, launches one independent supervisor per attempt, records supervisor process identity and the harness session ID before prompting, detects orphaned attempts, creates sequential recovery attempts, accepts durable cancel requests from unrelated processes, accumulates reported usage across attempts, derives a bounded result, implements repeatable wait, and provides read-only list/inspect operations over the state directory. The fake harness replays fixtures, including replay on `session/load`, and scripts resume acceptance or refusal plus honored or ignored cancellation; the contract suite drives fake and real harnesses through the same client API.

Claude and Codex launch, wait, recover, cancel, and Observe are implemented across the SDK, CLI, and MCP. `sub list` / `sub_list` return compact task status and usage; `sub inspect` / `sub_inspect` return the same task data plus every sequential attempt and normalized event. These reads require only the state directory and work while a detached supervisor runs, after it exits, or while an attempt is orphaned. `sub recover` / `sub_recover` create attempt N+1 only for an orphaned latest attempt and resume its exact harness session through the bridge; failure to resume is terminal for the new attempt and never becomes a fresh session. `sub cancel` / `sub_cancel` create a per-attempt request marker for a live supervisor and return immediately; the supervisor sends ACP cancellation, waits at most five seconds for acknowledgement, and publishes a terminal partial result even when the harness ignores cancellation. Events contain task/attempt linkage, started/orphaned/resumed/cancelled/finished lifecycle, coalesced activity categories, and accumulated reported usage; they never copy transcript content. The vendor-native session record remains raw evidence by reference. Claude reports cost and tokens, Codex reports tokens, and unsupported measurements remain null beside explicit `usage_support` flags. Rationale: [`decisions/2026-09-01-observe-events-and-usage.md`](decisions/2026-09-01-observe-events-and-usage.md), [`decisions/2026-09-01-orphan-detection-and-status.md`](decisions/2026-09-01-orphan-detection-and-status.md), [`decisions/2026-09-01-recovery-resume-mechanics.md`](decisions/2026-09-01-recovery-resume-mechanics.md), [`decisions/2026-09-01-cancel-request-signalling.md`](decisions/2026-09-01-cancel-request-signalling.md), and [`decisions/2026-09-01-cancel-grace-and-ignored-harness.md`](decisions/2026-09-01-cancel-grace-and-ignored-harness.md).

Public shapes are proposed in pull requests; no `sub.toml` is required for the beta path because every required launch value and state directory can be supplied explicitly.

Pinned dependencies are declared once in the root `Cargo.toml` under `[workspace.dependencies]` with exact (`=`) versions; crates reference them with `.workspace = true`. Lints are also workspace-wide (`[workspace.lints]`).
