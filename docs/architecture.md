# Architecture: crate layout

`sub` is one Cargo workspace. The SDK is the kernel; every other crate consumes it. Rationale: [`decisions/2026-08-27-workspace-layout.md`](decisions/2026-08-27-workspace-layout.md).

| Crate | Kind | Role |
|:--|:--|:--|
| `sub-sdk` | library | The kernel: the delegated-work model, beta-minimum `sub.toml` discovery, and the SDK. Owns the shared ACP client layer (`sub_sdk::acp`) and depends directly on the ACP SDK crate. |
| `sub-cli` | binary `sub` | Command-line surface for humans: onboarding, bridge install, launch, wait, recover, cancel, list, and inspect. |
| `sub-mcp` | binary `sub-mcp` | MCP stdio server for agents: bridge install, launch, wait, recover, cancel, list, and inspect. |
| `sub-harness-fake` | library and binary `sub-harness-fake` | Programmable fake harness (ACP v1 over stdio) for the behavioral contract suite. Owns fixture loading, scenario scripting, and the replay server. Depends directly on `sub-sdk` and the ACP SDK crate. |
| `sub-adapter-claude` | library | Adapter for `claude`, through pinned `@agentclientprotocol/claude-agent-acp` 0.70.0. |
| `sub-adapter-codex` | library | Adapter for `codex`, through pinned `@agentclientprotocol/codex-acp` 1.6.2. |
| `sub-adapter-cursor` | library | Adapter for `cursor-agent`, which speaks ACP v1 natively and requires no bridge. |

Dependency direction: surfaces → adapters and `sub-sdk` → `agent-client-protocol`, `tokio`; `sub-harness-fake` → `sub-sdk`, `agent-client-protocol`, `tokio`. Only `sub-sdk` and the programmable fake depend directly on ACP types. Adapters construct SDK launch data and never depend on a surface.

The shared ACP client layer in `sub-sdk` spawns an agent into an owned process group, negotiates protocol v1, creates, resumes, or replay-loads a session with adapter metadata, sets the requested harness-native permission mode and optional model, sends a prompt, consumes the update stream, captures unstable per-turn token usage, denies permission requests, cancels, and times out. It terminates the owned group and waits for the direct child before returning a force-cancelled outcome. The delegated-work kernel writes task/attempt state and a typed normalized event log, launches each supervisor directly into a detached Unix session, records the supervisor's PID plus platform start identity on Linux and macOS, detects orphaned attempts without a PID-only fallback, creates sequential recovery attempts, accepts durable cancel requests from unrelated processes, accumulates reported usage across attempts, derives a bounded result, implements repeatable wait, and provides read-only list/inspect operations over the state directory. The fake harness replays fixtures, including replay on `session/load`, and scripts resume acceptance or refusal plus honored or ignored cancellation; the contract suite drives fake and real harnesses through the same client API.

Claude, Codex, and Cursor launch, wait, recover, cancel, and Observe are implemented across the SDK, CLI, and MCP. `sub list` / `sub_list` return compact task status and usage; `sub inspect` / `sub_inspect` return the same task data plus every sequential attempt and normalized event. These reads require only the state directory and work while a detached supervisor runs, after it exits, or while an attempt is orphaned. `sub recover` / `sub_recover` create attempt N+1 only for an orphaned latest attempt and reopen its exact harness session; Claude and Codex use `session/resume`, while Cursor uses `session/load`. The shared client consumes but does not observe load-replayed updates before the load response, so attempt N+1 does not duplicate historical activity, changed files, result text, or usage. Failure to reopen is terminal for the new attempt and never becomes a fresh session. `sub cancel` / `sub_cancel` create a per-attempt request marker for a live supervisor and return immediately; the supervisor sends ACP cancellation and waits at most five seconds for acknowledgement. If the harness ignores cancellation, `sub` force-terminates its process group and waits for the direct child before publishing the terminal partial result. Events contain task/attempt linkage, started/orphaned/resumed/cancelled/finished lifecycle, coalesced activity categories, and accumulated reported usage; they never copy transcript content. The vendor-native session record remains raw evidence by reference. Claude reports cost and tokens, Codex reports tokens, and Cursor reports neither; unsupported measurements remain null beside explicit `usage_support` flags. Rationale: [`decisions/2026-09-01-observe-events-and-usage.md`](decisions/2026-09-01-observe-events-and-usage.md), [`decisions/2026-09-01-orphan-detection-and-status.md`](decisions/2026-09-01-orphan-detection-and-status.md), [`decisions/2026-09-01-recovery-resume-mechanics.md`](decisions/2026-09-01-recovery-resume-mechanics.md), [`decisions/2026-09-01-load-replay-observation-boundary.md`](decisions/2026-09-01-load-replay-observation-boundary.md), [`decisions/2026-09-01-cancel-request-signalling.md`](decisions/2026-09-01-cancel-request-signalling.md), [`decisions/2026-09-01-cancel-grace-and-ignored-harness.md`](decisions/2026-09-01-cancel-grace-and-ignored-harness.md), [`decisions/2026-09-02-portable-unix-supervision.md`](decisions/2026-09-02-portable-unix-supervision.md), and [`decisions/2026-09-02-cancel-force-termination.md`](decisions/2026-09-02-cancel-force-termination.md).

`sub.toml` is discovered at `$XDG_CONFIG_HOME/sub/sub.toml`, falling back to `$HOME/.config/sub/sub.toml`; `SUB_CONFIG` selects an exact path for tests and isolated runs. Its beta schema contains only `state_dir` and `harnesses.<name>.{binary,model,permission_mode}`. CLI or MCP arguments override configured values. Configured values flow into the same `LaunchParams` used by the explicit path, and binary paths have no built-in or `PATH` fallback. Rationale: [`decisions/2026-09-01-sub-toml-location-and-precedence.md`](decisions/2026-09-01-sub-toml-location-and-precedence.md).

`sub onboard <claude|codex|cursor>...` is the explicit user onboarding action. For each named configured harness it ensures the pinned bridge where required, installs one short `sub-delegation` skill in the harness's user skill directory, and upserts a `sub` stdio MCP registration pointing to the installed `sub-mcp` binary. Cursor's bridge action reports `not_required` because `cursor-agent acp` is native. It preserves unrelated harness configuration, reports each component as `installed`, `created`, `updated`, `unchanged`, or `not_required`, and validates the complete requested harness set before writing. All destinations have environment overrides used by tests and the onboarding scenario. Rationale: [`decisions/2026-09-01-onboarding-installation.md`](decisions/2026-09-01-onboarding-installation.md) and [`decisions/2026-09-01-cursor-native-acp-and-extensions.md`](decisions/2026-09-01-cursor-native-acp-and-extensions.md).

Pinned dependencies are declared once in the root `Cargo.toml` under `[workspace.dependencies]` with exact (`=`) versions; crates reference them with `.workspace = true`. Lints are also workspace-wide (`[workspace.lints]`).
