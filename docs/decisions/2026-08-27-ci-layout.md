# CI: GitHub Actions layout

Date: 2026-08-27. Status: adopted.

## Decision

Three workflows under `.github/workflows/`: `per-commit.yml` (pushes to any branch other than `main`/`staging`, and pull requests into `staging`) runs `scripts/verify.sh`; `full.yml` (pull requests into `main`, pushes to `main`) runs `scripts/verify.sh --full` with the `CS_ACCESS_TOKEN` secret; `nightly.yml` (daily at 06:17 UTC and on demand) runs the vulnerability and freshness checks. Actions run on `ubuntu-latest` with the pinned toolchain and tool versions; a later release workflow is generated by `cargo-dist`.

## Rationale

The mental model names GitHub Actions and defines which gate runs where; this layout maps each gate to one workflow that calls the same script developers run, so CI cannot drift from local verification. The harness-compatibility nightly needs real installed harnesses and is therefore a script under `scripts/nightly/`, documented in `docs/nightlies/`, not a workflow. Pushes to `staging` itself run no workflow because every commit reaching `staging` arrives by a pull request that already ran the per-commit gate, and rulesets forbid direct pushes.

## Revisit when

A macOS runner is needed for release builds (cargo-dist adds it), or the full gate needs a step that cannot run on a hosted runner.
