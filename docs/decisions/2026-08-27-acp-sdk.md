# ACP SDK: `agent-client-protocol` 2.0.0

Date: 2026-08-27. Status: adopted.

## Decision

The official Rust SDK crate `agent-client-protocol`, pinned exactly to `2.0.0`, which was the latest stable version on crates.io on 2026-08-27 (published 2026-07-23). It is a dependency of `sub-sdk` only. `sub` targets ACP protocol v1; the crate's `unstable_protocol_v2` feature stays off. Unstable features such as `unstable_end_turn_token_usage` are enabled in `sub-sdk` when the adapters need them, never at the workspace level.

## Rationale

The ACP boundary spike (`docs/spikes/acp-boundary.md`) drove all three harnesses through this exact crate version and negotiated protocol v1 with each of them, so pinning to it carries the spike's evidence forward into the scaffold unchanged. It is the protocol maintainers' own SDK, generated from the same schema the bridges implement, which is the smallest possible surface to audit for wire compatibility. Confining it to `sub-sdk` keeps the mental model's boundary: adapters and surfaces see `sub`'s delegated-work semantics, not ACP types. The alternative, hand-rolled JSON-RPC as in the spike's probes, would duplicate the schema and put wire compatibility on `sub`.

## Revisit when

The bridges advertise protocol v2 (then enable the v2 feature behind a spike), or a needed capability is only in a newer crate release.
