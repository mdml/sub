# Releases

No release has been made. This page describes the configured tooling and what remains before the first one. Rationale: [`decisions/2026-08-27-release-tooling.md`](decisions/2026-08-27-release-tooling.md).

## Tooling

`cargo-dist` 0.32.0, configured in `dist-workspace.toml`. `.github/workflows/release.yml` is generated by `dist generate` and must not be edited by hand; regenerate it after changing `dist-workspace.toml`.

On every pull request the workflow plans and, according to cargo-dist's PR mode, validates the release build without publishing. On a pushed tag matching cargo-dist's semantic-version pattern (for example `v0.1.0`), it builds the `sub` and `sub-mcp` binaries for macOS (arm64, x86_64) and Linux (x86_64, arm64), writes `sha256` checksums, attests every artifact with GitHub artifact attestations (Sigstore, keyless), publishes a GitHub Release, and pushes a Homebrew formula to the tap.

## Channels

| Channel | How it is served |
|:--|:--|
| `brew` | Formula generated by `cargo-dist` into the tap `mdml/homebrew-tap`. |
| `mise` | `mise use ubi:mdml/sub` installs from the GitHub Release; nothing to publish. A `mise` registry entry can follow once releases exist. |
| `cargo binstall` | Reads the release archives by their `cargo-dist` naming; no extra publishing. |

## Before the first release

1. Create the tap repository `mdml/homebrew-tap` and add a `HOMEBREW_TAP_TOKEN` secret with push access.
2. Decide the version (the workspace is `0.0.0`), update `CHANGELOG.md`, and push a cargo-dist-compatible semantic-version tag such as `v0.1.0` from `main`.
3. Verify checksums and attestations on the published release (`gh attestation verify`).
